- **Validation:** Zod **v4** (4.4.3) — target the v4 API. NOTE: `z.record(enumKey, val)` makes ALL keys required; use `z.partialRecord(...)` for sparse serde HashMaps (e.g. keybindings).

- **Type safety across IPC:** `tauri-specta` v2 generates `ui/src/ipc/bindings.ts` from Rust types (story 005; placeholder hand-authored in 006).
- **Testing:** Vitest 4 + React Testing Library + `@tauri-apps/api/mocks` + **jest-axe** (10.0.0, NOT vitest-axe — chose jest-axe per pins). jsdom required.

## IPC WIRE FORMAT (verified against real Rust code 2026-06-04 — CORRECTS earlier camelCase note)
- `AppSettings` and ALL its sub-structs (`luminos-core::config::schema`) have **NO `#[serde(rename_all)]`** → wire JSON keys are **snake_case** (`zoom_level`, `color_filter`, `tracking_mode`, `docked_edge`, ...). Mirror snake_case in Zod schemas; do NOT camelCase them.
- Enum *variants* serialize as bare **PascalCase** JSON strings (`"FullScreen"`, `"Cursor"`, `"None"`, `"Bilinear"`, `"Q8"`). Verified in `luminos-types::{state,gpu,overlay}.rs` serde roundtrip tests.
- **`FrameTimingSummary` is the ONE exception:** story 005 (DC-5) adds `#[serde(rename_all="camelCase")]` → wire keys camelCase (`averageMs, p99Ms, minMs, maxMs, targetFps`). Rust struct itself is snake_case (`average_ms` ...) with no serde derive today.
- Rust `Option<T>` → JSON `null` (use `.nullable()` in Zod, not `.optional()`).

## Key Conventions
- IPC commands: tauri-specta default error mode wraps fallible `Result<T,String>` cmds as `{status:"ok",data:T}|{status:"error",error:E}`. The `ipc/commands.ts` wrapper unwraps this (throws on error) so components use plain try/catch.
- Optimistic updates: update Zustand store immediately, call IPC, revert (re-set prior value) + error toast on reject.
- All IPC responses parsed through Zod schemas in the command wrappers (`appSettingsSchema.parse`, `frameTimingSummarySchema.parse`).
- Components/store depend ONLY on `ipc/{commands,events}.ts` wrappers, never on `bindings.ts` directly — swapping generated bindings is a one-file change.

## Tooling gotchas (verified E04/006)
- pnpm 10.33.4 via corepack (`packageManager` field). esbuild needs `pnpm.onlyBuiltDependencies:["esbuild"]` in package.json or `vite build` fails (no native binary).
- eslint-plugin-react-hooks v7 `configs['recommended-latest'].plugins` is a legacy ARRAY → flat config rejects it. Register `plugins:{'react-hooks':reactHooks}` + spread only its `.rules`.
- jest-axe ships NO types; write a local `jest-axe.d.ts` + a vitest `Assertion` augmentation for `toHaveNoViolations`. Don't pull `@types/jest-axe` (drags in `@types/jest`, conflicts with vitest globals).
- jsdom does NOT change `<input type=range>` value on arrow keys → use `fireEvent.change(slider,{target:{value}})` (documented RTL exception); assert keyboard-operability via role/focus separately.
- vitest config: set `clearMocks:true` + `unstubEnvs:true` so polling components (FrameTimingDisplay) don't leak mock-call history across tests.
- Toast/context pitfall: keep toast ACTIONS stable (memo on stable callbacks, separate from the toasts array) or a `useEffect` depending on the toast object loops (hydrate→toast→re-render→hydrate).
- axe: a bare `<div aria-label=...>` with no role fails `aria-prohibited-attr`; add `role="region"`.

## IPC Architecture
- Commands: Panel→Engine via `invoke()`; Events: Engine→Panel via `emit()`/`listen()`
- Commands run on Tauri async tokio runtime — never block render thread
- State mutations: write to `ArcSwap<AppState>`, then send `EventLoopProxy` event to wake winit
- Hotkey changes flow back to panel via emitted events (`zoom_changed`, `settings_changed`)

## Accessibility (Non-Negotiable)
- Control panel must meet WCAG 2.1 AA (users are low-vision — inaccessible panel = critical bug)
- All CSS sizes in `rem`. `global.css` (E04/006) handles a11y media/modes concretely:
  - `prefers-reduced-motion: reduce` → near-zero animation/transition durations
  - `prefers-contrast: more` → real `@media` block that thickens focus ring + key borders
  - forced-colors / high-contrast → handled IMPLICITLY by using CSS system color tokens everywhere (Canvas, CanvasText, Highlight, GrayText) — no `forced-colors` override block needed
  - disabled state: use `color: GrayText` NOT `opacity` (opacity is ignored in forced-colors)
  - Don't claim a11y coverage in comments that the CSS doesn't actually implement (reviewers flag this on an a11y product).
- ARIA live regions on all dynamic status (TTS state, zoom level, model loading)
- Codebase rule confirmed: ZERO type assertions — prefer `String(error)` over `error as string` in catch blocks.
